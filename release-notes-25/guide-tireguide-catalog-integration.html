Retail – TireGuide Catalog Integration

A comprehensive set of features aimed at enabling the integration between TireWorks HD Retail and the TireGuide catalog.

Centralized TireGuide Database & TireGuide Service

TireWorks utilizes the TireGuide catalog through standardized web service communication, consistent with its approach for other catalogs. The TireGuide data resides in an internally maintained database constructed to meet TireGuide-specific requirements. This database schema can be deployed via scripts wherever a new instance of the TireGuide database is needed.

The catalog service works uniformly across various catalog types; for TireGuide, the “CatalogType” key is set to “TireGuide,” and the connection string points to the designated TireGuide database populated with relevant data.

Simplified Order Options & F2 Menu

When TireGuide is configured as a locations catalog, the F4 Diagnosticator and F6 FSM buttons, along with their associated functionality, are intentionally omitted. This is because TireGuide is dedicated exclusively to providing accurate tire fitment data for vehicles and does not contain the information required for these additional functions.

Users may also observe the omission of certain packages within the F2 Packages menu; any packages containing "Catalog Part" or "Catalog Labor" items are automatically excluded from search results, and the "Parts" and "Labor" tabs will no longer be displayed. This adjustment aligns with TireGuide's exclusive focus on tire fitment.

Tire fitments sourced via TireGuide can be saved directly to a vehicle record and seamlessly utilized in F1 searches, consistent with processes applicable to fitments acquired from other catalogs.

Updated Vehicle Creation and Details UI

When TireGuide is set as a locations catalog, users will observe changes to the Vehicle creation UI. For other catalogs, the interface displays Year, Make, Model, and Engine as four dropdown fields for defining the vehicle. In contrast, the TireGuide catalog presents Year, Make, Model, and Option, with the fourth field reflecting trim or submodel instead of engine size.

Switching from another catalog type to TireGuide may require vehicles previously created under the former catalog to be updated and saved again to ensure compatibility.

Additionally, the “Oil Settings,” “Conditions,” and “Vin Details” tabs are no longer present in the Vehicle Details UI when TireGuide is the selected catalog, as this information is unavailable in this configuration.

“Add Vehicle” Quick Button

With this integration, an “Add Vehicle” button has been implemented on the F1, F2, and F3 screens. This feature enables users to add a vehicle to an order without closing the current screen. The vehicle is then assigned to the order, making options such as Tire Fitment information available immediately, without requiring the user to close or reopen their window.

The “Add Vehicle” button is also present on the Home Screen, located below the “Quick Tire Search” field. When a vehicle is entered here, a quick quote will open with the selected vehicle assigned, and an F1 search will be initiated displaying the first Tire Fitment option from the catalog. If the entered Plate or VIN matches an existing customer, users will receive prompts to confirm whether they wish to use the existing customer and vehicle information, helping to prevent duplicate entries.

Simplified Catalog Updates

TireGuide utilizes a unified catalog of information rather than maintaining separate catalogs for each supplier. As a result, the data remains consistent for all users accessing the TireGuide catalog and can be efficiently managed within a centralised database, eliminating the need for multiple instances.

A dedicated service host has been developed to facilitate population of a TireGuide database compatible with our catalog service at any required location. Please note that configuration and operation details for this service host are restricted and not included with the general application distribution.
