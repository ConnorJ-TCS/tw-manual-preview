Retail – TreadNet | Bridgestone National Accounts & Vendor Ordering

A comprehensive set of features aimed at enabling the integration between TireWorks HD Retail and TreadNet.

New Special Program Attributes and Values

Program Key – “TREADNET”

“TREADNET” has been added as a recognized program key, which identifies the program as a TreadNet-integrated program to TireWorks HD.

Program Reconciliation

Program Reconciliation enables dealers to automate accounting for special programs through three primary transactions: ticket creation, customer credits to clear accounts receivable, and a vendor credit entry. The system calculates differences between customer and vendor credits and posts journal entries to reconcile receivables and payables. It is compatible with Great Plains, QuickBooks, and TireBooks, and allows configuration of variance and credit SKUs for tracking accuracy. Users can adjust reconciliation settings, including process automation and variance thresholds. Ticket and credit management is available within a reconciliation window, where items can be marked for review or completion. Additionally, the status of the vendor credit line is displayed in this window, allowing users to easily monitor and track the progress of vendor credits during the reconciliation process.

Accurate Billing Requirements

After a Fleet or Dealer is assigned to an order and the DR Type is identified, TireWorks HD displays the billing requirements that TreadNet needs for successful order submission and invoicing. Certain data points are shown or marked as mandatory based on responses to other requirements. If these data points are missing, the submission will not succeed. This process enables users to review requirements and provide valid inputs, with notifications for any potential issues before submission. TireWorks HD presents both allowed and mandatory billing requirements, including those affected by previous answers.

TreadNet Vendor Ordering

The integration introduces a new Order-capable Vendor Type, "Bridgestone Treadnet." Vendors assigned to this type will use the configured Inventory Lookup and Order TreadNet endpoints to obtain quantity and availability data from the TreadNet API during F1 Tire Searches. These results are displayed alongside information from other order-capable vendors. The system supports direct vendor submission of purchase orders for sourcing, standalone invoices, or autoreplenishment purposes.

UI/UX Enhancements

The process for creating and submitting a delivery receipt to TreadNet consists of multiple steps. The user interface has been modified to allow users to generate delivery receipts within the Service Request section without exiting the application.

“Bridgestone Firestone National Account” UI

When an order is linked to a TreadNet-integrated special program, a “TreadNet” button is displayed above packages and line items. Selecting this button allows users to modify delivery receipt details and submit them to TreadNet’s API.

Assigned Fleet/Dealer ID, Name, and DR Type are shown when opened. If these fields are unassigned, the “Bridgestone Firestone National Account Selector” window appears, prompting users to answer five questions that determine the DR type and assist in searching for and assigning a Fleet/Dealer to the order.

After a Fleet/Dealer is assigned, the “Requirements” tab is filled with mandatory fields based on the selected ID and DR type. The “Submission” tab shows a summary of DR data prepared for submission, including any warnings or errors that prevent submission. The “Status” tab displays the current TreadNet Submission/Invoicing status.

For TREADNET special program service requests, the Prod. Code field now automatically trims leading zeros from tire part numbers and the ‘Ctrl+F’ hover tooltip has been removed from the Prod. Code column, matching BSFS invoicing format and reducing UI clutter. Manually entered product codes and codes from other sources remain unchanged.

TreadNet Invoice PDF

After the delivery receipt is invoiced by TreadNet, the daemon process downloads the PDF as a Base64 string and stores it in the database. Users can access the TreadNet invoice PDF once it has been collected. This access is available via the “Status” tab in the “Bridgestone Firestone National Account” user interface or through the processed Vendor Credit associated with the order during program reconciliation.

A new "Link Bridgestone Invoice" button and selection window have been added to the AP Invoice screen for Bridgestone (TreadNet) vendors, allowing users to view, select, and link available Bridgestone invoices with PDF preview and improved sorting.

Expanded Tire Item Data Inputs

For certain DR types, specific data for Tire items may be permitted or required when submitting orders to the TreadNet API. When TireWorks HD identifies a DR type that necessitates this information, the “Add/Edit DoT Number” user interface will display these fields along with the DOT number.

These fields include Wheel Position, Barcode, OTR Serial Number, and Removed Tire DoT Number.

Required fields are indicated with a red asterisk.

Order Lockdown After Submission

For TreadNet orders, modifications to TireWorks HD data are restricted once the delivery receipt has been submitted to the API for review and invoicing. After submission from a Service Request, the order is locked within TireWorks HD, granting only basic read access until the invoicing process is complete and reflected in TWHD. Invoicing functionality becomes available upon completion of this process, except for users who possess the "Bridgestone NA – Edit Order Before DR is Invoiced" access right.

Occasionally, the delivery receipt submitted to TreadNet may be rejected, thereby requiring Dealer Action. Under such circumstances, the TireWorks HD order will become editable once again, allowing necessary dealer corrections prior to resubmission.

DR# Sequence

For programs utilizing the “TREADNET” program key, a “DR# Sequence” tab appears in the Manage Special Programs window. Assigning a numerical value to this field will automatically allocate the next sequential number to the “DR#” field within the “Requirements” tab of new TreadNet orders.

If the field is left blank, the “DR#” within the “Requirements” tab remains editable. When filled automatically, only users with the “Bridgestone NA – Override Auto DR Numbers” access right are permitted to modify this field.

Home Screen Filter Update

To help you quickly locate orders by their TreadNet DR Number or WebDRNumber, the home screen filter now searches both fields and displays matching results.

TreadNet Daemon Processes

To keep order statuses and invoice data current, the daemon must run regularly.

MainOptionID = 70

Checks the “DR Action Update” API for orders needing dealer action. Possible statuses:

  • Off tire DR hold
  • Rejected to Dealer
  • Service To party account hold
  • Servicing Party Account Hold
  • Waiting for PO

MainOptionID = 71

Checks the “DR Detail Update” API for submitted orders not yet invoiced. Updates TireWorks HD if order status changes.

MainOptionID = 75

Checks the “Invoice” API for invoiced orders and pulls invoice details and PDFs into TireWorks HD.

The DR Invoice job uses processed start and end dates based on the last run timestamp instead of DR numbers, and a new table records each job run and its details for improved accuracy and compliance with Bridgestone requirements.
