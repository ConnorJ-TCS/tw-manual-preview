QuickBooks Online - Tax Variance Alerts

A comprehensive set of features aimed at enabling tax posting validation for QuickBooks Online sales transactions in TireWorks HD. The feature compares the tax total returned by QBO to the tax total calculated by TWHD after an integration create completes, then alerts users when the variance exceeds configured thresholds.

The main business impact is reconciliation visibility. Stores and operations teams can continue posting transactions without the tax variance warning blocking the integration, while accounting users gain a structured way to review, filter, and acknowledge discrepancies that may otherwise stay hidden until reconciliation.

New Accounting Integration Settings

Enable Tax Variance Alerts

Turns on QBO tax variance alerting. When enabled, the related dollar and percent threshold fields become available and at least one threshold must be entered before saving. This setting only appears when the Accounting Integration is set to QBO.

Dollar Variance Threshold

Defines the dollar amount that a QBO tax difference can exceed before an alert is created. The field allows two decimal places and is visible only when Enable Tax Variance Alerts is checked.

Percent Variance Threshold (%)

Defines the percentage difference that a QBO tax difference can exceed before an alert is created. The field allows two decimal places and is visible only when Enable Tax Variance Alerts is checked.

Threshold Setup and Validation

The Tax Variance Alerts section is shown only for QBO accounting integrations. In Retail, it is added to Manage > Utilities > Accounting Integration on the General tab, below Integration Options. In Wholesale, it is added to the Accounting tab in the Manage Company window.

The dollar and percent thresholds use OR logic. If both thresholds are set, exceeding either one triggers the alert. If the setting is enabled and both threshold fields are blank, the user is prevented from saving and receives this message: "Enter a dollar threshold or a percent threshold before saving while Tax Variance Alerts is enabled." The empty threshold fields are also highlighted with a red outline.

Tax Posting Validation

Tax validation runs after TWHD creates the QBO sales or refund document and QBO returns its tax total. The supported document types are Invoice, Sales Receipt, and Credit Memo/Refund Receipt. TWHD compares the QBO tax total against the TWHD tax total calculated from the same transaction dataset.

When the variance exceeds the configured dollar threshold or percent threshold, TWHD records an audit entry and appends a warning to the existing integration message. The expected warning format is: "Tax variance warning: TWHD X.XX vs QBO X.XX (delta $Z.ZZ)." In Retail, the message is stored in SrHeader when Use Integration Manager UI is false and in IntegrationHistory when it is true.

The warning does not change the normal integration success or failure result. Existing integration errors still behave as before, and a tax variance produces a warning and audit record rather than blocking a successful integration.

Integration Alerts

The Integration Manager includes a new Integration Alerts tab for reviewing active QBO tax variance warnings. Existing Integration Manager functionality remains available, and the alert tab gives users a centralized place to see and acknowledge unread variance records.

  • Alerts display for all locations by default.
  • Users can filter by Location and by Document Type. The document type choices are Invoice, Sales Receipt, and Credit Memo/Refund Receipt.
  • The alert grid shows Location, Document Type, Document Number, Transaction Tax Details, Alert Message, and Alert Date/Time.
  • The Alert Message is built from the stored TW tax total, QBO tax total, and variance amount, using the format: "Tax variance exceeds configured threshold. Transaction tax: $X.XX. QBO tax: $Y.YY. Variance: $Z.ZZ."
  • Users can select one or more alerts and click Mark as Read to acknowledge them. This action immediately updates the record and does not require a separate Save.
  • The tab includes a selection count below the grid so users can see how many alerts are currently selected.

Unread Alert Count and Refresh Behavior

The Integration Alerts tab displays a badge or bubble showing the total number of unread alerts. The badge displays 99+ when the unread count is greater than 99 and disappears when there are no unread alerts.

The unread count is global rather than filter-specific. Changing the Location or Document Type filters does not change the badge count. The count updates when the Integration Manager window loads, when Mark as Read is used, and when Refresh is clicked.

When Refresh is clicked while the Integration Alerts tab is active, the filters reset to their default values and the alert data is re-fetched. This keeps the alert review behavior consistent across Retail and Wholesale.

QBO Setup and Operational Notes

This feature applies only when the accounting system is QuickBooks Online. Validation is skipped when QBO is not the accounting system, when Tax Variance Alerts are disabled, when neither threshold is configured, or when QBO does not return a usable tax total.

Standard setup guidance continues to matter for this workflow. QBO should be configured as the accounting type for the TireWorks company, and QBO tax agencies/tax schedules should be set up and synchronized according to the QBO integration instructions.

The related tax-detail lockdown work restores protections on existing Tax Detail ID, Tax Agency for QBO, Tax Detail Type, and Tax Detail Percent fields. Those fields remain editable only while creating a new Tax Detail before the first save, which helps prevent avoidable mismatches between TWHD and QBO.

Observed testing indicates that some variances may occur when QBO automated sales tax behavior changes the tax result outside TWHD's direct control. The alert workflow is intended to surface those discrepancies for review rather than guarantee that every upstream QBO tax condition can be controlled from TWHD.
